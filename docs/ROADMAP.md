# «Лила» — план развития после MVP

Статус: живой документ, обновлять при закрытии каждого пункта
Начат: 2026-11-02
Предыдущие документы: [`PLAN.md`](PLAN.md) — план MVP (выполнен), [`UX_ITERATION_1.md`](UX_ITERATION_1.md) —
первая UX-итерация (выполнена), [`RULES.md`](RULES.md) — правила игры.

Главный принцип порядка: **сначала стабильность, безопасность и измерения, потом рост**. Продвигать
бота имеет смысл только после этапов 0–2: без них неизвестно, где теряются игроки, и любая ошибка в
оплате или safety бьёт по реальным людям.

## 1. Текущее состояние прода

| Параметр | Значение |
|---|---|
| Хостинг | Railway, тариф Hobby ($5/мес, включает $5 использования) |
| Сервисы | `api` (FastAPI), `bot` (aiogram, polling), Postgres |
| Публичный адрес API | `https://lila-api-production-456.up.railway.app` |
| Модель | `LLM_MODEL=claude-haiku-5-5` (ID пишется через дефисы, с точкой — 404) |
| Оплата | Tribute, тип товара digital product, вебхук `/payments/tribute/webhook` |
| Оплата проверена | да, реальной покупкой 2026-11-02: статус `processed`, подпись hex подтверждена |
| Админ | `ADMIN_TELEGRAM_IDS` на сервисе bot, команда `/grant <telegram_id> [count]` |

Открытые вопросы по проду:

- задан ли `TRIBUTE_PRODUCT_ID` на сервисе api (нужен, если товаров в Tribute больше одного);
- запущены ли cron-задачи `scripts/send_reminders.py` (раз в час) и `scripts/abandon_stale_games.py`
  (раз в день). Без них напоминания и `game_abandoned` не работают;
- настроен ли бэкап Postgres;
- была ли первая оплата при пустом адресе вебхука выдана через `/grant`.

## 2. Расходы

**Railway.** Счёт ~$2,81 за период: 98% — память, CPU и диск почти ноль. На Hobby это полностью
покрывается включёнными $5, поэтому **оптимизация инфраструктуры сейчас экономит $0**. Вернуться к ней,
когда использование подойдёт к $4: первым шагом объединить api и bot в один процесс (−$0,5–1/мес).

**LLM.** Оценка на партию (≈29,5 хода по `scripts/play_cli.py`, ответы на ~40% клеток, ~37 вызовов):

| Модель | ≈ $ за партию | Примечание |
|---|---|---|
| Haiku 4.5 | 0,09 | кэш промпта не работал: системный промпт ~780 токенов < минимума 4096 |
| **Haiku 5.5 (сейчас)** | 0,01–0,02 | кэш работает (минимум 512), подтверждено `cache_read_input_tokens` |
| Sonnet 5.5 | 0,2–0,3 | кандидат для «премиального ведущего» |
| Opus 5 | 0,6–1 | бывший дефолт в коде |

Это оценки, не замеры: токены пока не пишутся в БД (этап 2). При цене партии 299 ₽ себестоимость LLM
пренебрежимо мала на любой модели Haiku.

**Важно про Haiku 5.5 и новее:** мышление включено и расходует `max_tokens`. Лимиты в
`src/llm/guide.py` — потолки (1000/2000/3000), длину ответа задаёт системный промпт. Не опускать их
до размера ответа: при 350 токенах `deepen` возвращал пустой текст.
